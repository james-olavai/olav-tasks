# 整理项目文档

使用客户端原生文件工具，在用户选定项目和整理范围内工作。先看目录入口与已有索引，再搜索、读取相关段落；docs-kb 可用时先检索片段，但不是必需依赖。

本 skill 负责已有材料的导航、索引、重复内容和用户指定 backlog 的转换，不借整理新增需求或范围。需求、排序或依赖尚需收敛时使用 `olav-tasks-plan`；已明确内容落盘使用 `olav-tasks-write-markdown`。

- 沿用项目分类和命名，优先补索引与相对链接。普通 Markdown 不需要改成任务。
- 更新现有索引和文档，不额外创建重复权威副本。合并内容时保留出处、结论的时态和必要的历史依据。
- 将用户指定的 backlog 转成看板任务时，一项一个 Markdown，保留稳定 ID、现有状态、原验收条件和来源链接；不同记录冲突或状态不明时明确标注，不能推断为完成。
- 看板任务 frontmatter 必填 schema: olav.tasks/v1、唯一 id、非空 title、status: todo/in-progress/done；可选 priority: P0/P1/P2 和 depends_on: 真实任务 ID 数组。暂缓原因记正文，不增加状态枚举。
- 项目采用父子任务或外部门治理扩展时，保留并按已确认依据填写 parent: 父任务 ID、blocked_by: 阻塞说明；待用户决定或外部门须写 blocked_by 并在正文说明，解除后删除。父任务须子任务全部 done 且父级验收通过才能 done。当前 CLI/API 摘要不展示这些扩展，调度 ready 工作须读 frontmatter 原文，核对依赖全部 done 且无 blocked_by，不能仅凭摘要判断。
- 整理保留既有状态，不推断完成。状态 owner 与验收门遵项目规则；配合 loop-dev 时，执行者实际开始可记 in-progress，done 由协调者依据对最终成果的独立验收设置，执行者自述或子范围通过不足以关闭任务。
- 转换时说明迁入任务的新权威位置及旧记录用途，避免索引和旧表同时维护状态。转换前后的任务数量与 ID 对照核实；未转换范围保留原约定。
- 移动、重命名或删除需在用户要求范围内；先检查相关引用，只声明实际检查和修复过的范围。默认不批量搬动或删除既有文件。

结束时列出整理后的入口、实际修改的文件、未处理的冲突及链接影响范围。整理文档不改变实现或验收事实。
