# 执行 Olav Tasks

先读项目协作规则、任务原文和 [工作包与验收](references/work-package.md)。项目和用户的权限边界优先。本 skill 在当前活跃会话中编排，不授予提交、推送、部署或跨项目修改权限，也不启动后台服务或外部代理。

用 `olav-tasks tasks ready <项目目录> --json` 取得只读快照；仅在 `complete: true`、无诊断时考虑 `tasks` 中的候选。CLI 输出不占有任务，派工前重读任务原文、确认版本和当前工作树，并核实 `depends_on`、`parent`、`blocked_by` 与项目规则。图或扫描不完整时停止派工并报告。若 CLI 不可用，直接按契约读取全部相关原文且能证明扫描完整后才选择；不能证明则停止。

按任务验收条件划定一个可审查工作包，指定单一文件 owner、边界、执行体与停止条件。优先使用当前宿主提供且项目允许的原生 Codex/Claude subagent；不通过 shell 新开 codex/claude，也不自动调用外部 pi。按[工作包与验收](references/work-package.md)传递最小且完整的任务上下文；宿主允许时实施与独立 QA 分别优先用新上下文，受限时记录实际复用方式，不改变不同 owner 的 QA 门。reasoning 按风险独立选取并记录实际宿主能力。模型档位仅是提示，以项目映射和当前宿主可用性为准，`effort` 不决定模型。共享目录中同一文件串行写；提交与暂存使用一个协调者维护的 index 锁。

执行者实际开工后按项目约定将任务记为 `in-progress`。执行完成后由不同于实施者的代理做独立 QA，检查最终工作树与真实验收条件。失败给实施者返修，最多两轮；仍失败则停止、记录证据并重拆任务，不标 `done`。独立 QA 通过后协调者核验范围与状态；只有此前用户或项目已授权提交时才精确暂存属于本包的文件并提交，避免无关 dirty。推送、发布和部署仍需各自授权。

协调者在最终验收通过后按项目规则更新任务正文证据和 `done`，父任务还须所有子任务完成及自己的独立验收。按[工作包与验收](references/work-package.md)汇总完整工作包的用量、费用和耗时，未知值标未知。再次查询 ready，继续下一项，直到没有候选、出现阻塞或会话结束。快照与状态变化不构成后台调度承诺。
