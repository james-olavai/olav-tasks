# 工作包与验收

派工记录任务 ID、原文路径与版本、目标和可观察验收、基点 revision、可写文件、禁写文件、执行体及实际模型、测试命令、停止条件。接口未定或文件 owner 冲突时先定边界。同一文件只安排一个写者；子任务可并行时仍由协调者串行处理共享索引和 Git index。

独立有界包在宿主支持时优先以 `fork_turns="none"` 启动新代理；确需会话决策时仅传必要的有限轮次。宿主不支持该参数或已达到线程限制时，记录原因与实际复用方式，不虚称新上下文，也不自动换外部执行体。最小简报仍须带上项目规则及必读文件路径、父级契约与当前授权边界、任务原文及版本、验收和反例、文件 owner/白名单、相关 dirty 基点、获准检查与停止条件；代理须自行完整读取必读规则，不得以简报或短摘录绕过。宿主允许时实施与独立 QA 分别优先使用新上下文；QA 始终由不同 owner 读取原文和最终证据，不继承实施者的自评。同包返修交原实施代理，优先仅传失败证据与变更面；上下文过大时先留下可核的 checkpoint 简报，再以宿主允许的新上下文交原代理或等价续接，并记录实际方式。返修轮次上限不变。

派工简报只附当前包必需的原文路径、版本、短摘录和证据入口，后续按需定位原文件。工具调用从源头限制检索范围、日志行数和返回长度；默认回传结论、路径/行号、命令/cwd/退出码、证据文件位置和未决问题。原始日志保存为可核文件，审查需要时再读取；不能先生成大量工具输出、事后仅在 UI 截断或隐藏来声称节省 token。精简输出不免除实际测试、原始证据、QA 复核或必读规则。

`effort` 工作量、模型能力档位与 reasoning effort 分别决定；reasoning 依包的技术与资金/权限风险选择，不默认继承父会话的高档。记录请求值及实际值；宿主不能逐包设置或无法核实实际值时记“宿主默认”或“未知”，不把建议值写成已执行事实。

独立 QA 至少核对任务原文、最终 diff、实际测试输出、未知改动和项目规则；测试通过不替代行为验收。实施者不能给自己做最终 QA。返修轮次记录失败原因和结果，最多两轮；若两轮后仍不满足验收，停止并将任务拆成可独立验收的子任务，保留真实状态及阻塞说明。

状态更新前再次读取文件版本；发生外部更改则重新核对并合并，不能覆盖。`ready` 的 `revision` 只标识扫描快照，不能当写锁或任务租约。父级任务不能因子任务全部完成自动设为 `done`；必须核对父级目标。提交时只暂存明确归属文件并检查 staged diff；无授权则保留可审查结果。记录 commit、QA、CI、发布各自事实。

仅按完整已验收包记录成本与用量，覆盖 root 编排、检索、实施 worker、独立 QA、返修与失败尝试及验证。按参与者分别记可得的 input、cached input、output、reasoning output、费用、耗时及计量来源和覆盖关系。cached input 若已含在 input、reasoning output 若已含在 output，均只作分项展示，不重复相加；root usage 若已含子代理，子项也只作分解。覆盖关系未知时全包总量记“未知/部分覆盖”，不能相加猜测。缓存价格影响、token 总量和并行墙钟耗时分别列示；缺失项写“未知”，不可当零或据此推算真实节省。汇总和比较须采用一致口径，首轮通过率及返修轮次也只以已验收包为样本。
