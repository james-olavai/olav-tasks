# docs-kb Markdown 检索与长文定位

## 目标

将 docs-kb 配套到 Olav Tasks，让 Agent 在写作和整理之前检索本地项目资料，并返回可核对的原文件位置。

## 来源与已核实边界

- 参考来源：olav-os 的 `experiments/t-37-human-ai-swarm-skeleton/studio-defaults/positions/system-file-organizer/skills/docs-kb/`，按原仓库 MIT 许可核对复用并保留署名。
- 当前实际随技能提供四个 Python 脚本：classify、search_docs、add_frontmatter、check_taxonomy_drift；依赖 Python 与 PyYAML。
- README 还描述 init_config、extract_docs 和 ocr_extract，但当前该目录没有这些脚本。不得把 README 的完整能力清单当作已可移植实现。
- 现有检索对大于 64 KiB 的 Markdown 做内存分段，按原文件与行号输出，不拆写源文件；检索未命中日志写在 skill 目录，需适配 npm 安装目录可能只读的情况。

## 第一版范围

- 创建可独立安装的 docs-kb skill，移除 Studio 岗位绑定与固定工作区假设，复用明确的任务与文档契约。
- 提供项目根目录内的 Markdown 全文检索、有效 frontmatter 过滤和长文段落定位；结果包含相对文件路径、原始行号和内容片段。
- Node/npm 安装后核心检索可用：将必要检索逻辑适配为 Node CLI，不让第一版必需 Python/PyYAML。先交付字面关键词查询、元数据筛选、上下文片段与结构化输出；分类自动化、同义词配置与批量 frontmatter 写入按真实需求后续增加。
- 先交付独立 docs-kb skill 与显式目标目录安装命令；写作与整理 skills 后续调用同一套检索能力。引用源文件，不能将索引或搜索结果变成平行事实源。
- 普通文档分类使用项目已有约定；报告建议即可。frontmatter 写入属于显式整理动作，不能因检索自动改文件。
- 保留任务 `schema`、`id`、`status`、`priority`、`depends_on` 和未知字段。文档生命周期状态不得覆盖看板的 todo/in-progress/done。
- 全部路径限定指定项目根，排除 .git/node_modules/构建缓存并拒绝 symlink 逃逸；没有明确根目录时不回退到 npm 包目录扫描。
- PDF、Office、OCR 转换后置，第一版不自动安装 Python 或系统 OCR 依赖。

## 验收条件

- 从本地 npm 包安装并安装 skill 后，Agent 可检索指定项目的 Markdown，无 Studio 或 Python 运行依赖。
- 在本项目与一个长 Markdown 示例上查询：能返回正确文件、原文行号与片段，长文件不被拆分或重写。
- 任务状态筛选与普通文档元数据互不覆盖；重复/无效 frontmatter 可诊断，单个坏文件不使整个搜索失败。
- 搜索不会写源文档或 npm 安装目录；需要诊断记录时使用明确的可写位置并说明其非权威用途。
- docs-kb skill 的命令与结果引用方式可执行，供后续写作/整理 skill 使用；安装方式、必要 CLI/资源、许可证与 npm 包清单一致。
