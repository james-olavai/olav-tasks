# 支持原生代理开发闭环与任务就绪查询

## 用户决定与目标

2026-10-03 用户要求提升 Olav Tasks，使其承担任务选择、原生子代理执行、独立 QA、返修及按授权提交的闭环。交付自包含的 olav-tasks-execute skill 和可信的只读候选查询；本轮保留 loop-dev，不修改 Vela 项目治理规则。

## 范围与不变量

- typed Task、API 和只读网页支持可选 parent、blocked_by；旧任务兼容，Markdown 原文仍是唯一权威。
- 增加 tasks list / tasks ready，只读扫描。扫描不完整、解析或读取异常时不返回可派工候选；依赖与父链的缺失、重复和循环不能被 done 状态掩盖。
- ready 仅返回快照候选，不授予执行权限或占有任务。未完成子任务阻止父任务进入最终验收候选；子任务全部 done 不自动关闭父任务。
- execute skill 遵项目角色与权限，使用获准的原生执行体；不同代理独立 QA，最多两轮返修后重拆。协调者依据最终验收设置 done；提交须已有授权且精确控制暂存。
- 仅保障活跃代理会话持续推进；不新增后台调度、Agent SDK、外部路由、执行按钮或生产部署。
- 更新三个写作 skills、契约与分发说明，构建用户级 CLI 并安装第五个 skill。保留旧 skills 的外置备份，不改变通用安装器的拒绝覆盖规则。

## 验收条件

1. 字段解析、状态写回保真、候选排序、blocked、依赖和父链异常、未完成子任务、扫描失败均有行为验证，真实 CLI 输出正确且不修改项目。
2. 类型检查、受影响测试和生产构建通过；API 与网页桌面/窄屏实际显示父级与阻塞。
3. 五个 skills 格式有效、源与本地安装一致，npm 包可分发并运行实际任务查询。
4. 独立代理在隔离 Git fixture 完成执行、独立 QA、返修、精确提交与继续下一项；外部阻塞及图错误不派发，无关 dirty 不进入提交，父级独立验收后才 done。
5. 两轮返修失败后的停止重拆有独立行为证据；不把静态文字检查记为完整闭环。

- 提交、推送和退役旧 loop-dev 为独立事实；本轮未默认公开发布或改写其他项目规则。
