# 收紧 docs-kb 输出以减少 LLM token

## 目标

用户强调检索的目的是减少 LLM 对大文件的读取消耗。8 MiB 是本地扫描上限，不是模型输入上限；实际需要约束整次检索输出并指导 Agent 只读命中行附近内容。

## 范围

- 默认最多 5 个文件，每个片段最多 600 字符，并保留真正命中内容与原行号。
- 整次标准输出默认最多 6000 字符，涵盖结果、元数据与诊断；通过 `--max-chars` 显式调整。字符预算是近似控制，不声称等于固定 token 数。
- JSON 使用紧凑格式；文本与 JSON 都受预算限制，不能只缩正文而留下巨量元数据。
- 因预算删减时明确 `truncated`；保留可用的结果优先于过多诊断。单项超预算时缩短无关元数据或跳过并诊断，不裁断 JSON 或文件路径造成无效引用。
- Skill 指导先检索片段，有必要才按行号读取小范围原文；不因命中文档就直接读取整个大文件。
- 保留 8 MiB 本地扫描上限与长文件定位；不因文件较长就默认丢失可检索内容。

## 验收条件

- 默认搜索最多 5 文件、单片段不超过 600 字符、stdout（包含结尾换行）不超过 6000 字符。
- `--max-chars` 对 JSON/文本都有效；大元数据、长行、大量诊断不越预算。参数错误给出明确说明。
- 短结果保留原行号；超过 64 KiB 的文档仍可定位深处内容，源文件未变化。
- 重新生成本地 npm 包并验证隔离安装，配套 skill 和 README 与实际输出一致。
