# 修复 Codex 聊天恢复与用量完整性

## 验收条件

- thread.started 返回非空 ID 后立即可靠保存；进程重载后使用原 ID 恢复，只传新消息。已有聊天历史但缺 ID 时明确失败，不静默新建线程丢失上下文；关键保存失败可见。
- 失败、取消或中断且没有完整 usage 的尝试标记 partial/unknown，保留已知 subtotal；后续成功和重载不能抹掉缺口。旧状态缺字段不被推断为完整。聊天面板及既有运行面板都显示完整性；计数明确是已统计回合。
- 保存的请求模型传入 SDK start/resume；没有模型记录的新会话仍由 SDK 默认处理，不把请求模型称为已核实实际模型，不由 effort 推导模型。
- completed 正常结束才 idle；turn.failed、异常、提前 EOF 为 failed，主动取消为 stopped；失败不执行正常完成后的自动检查。所有出口关闭上游迭代器并清理待决许可、监听与运行状态。
- 模块级 SDK mock 执行真实 adapter 和运行状态逻辑，覆盖恢复、失败后成功、重载、模型、五种流出口及资源清理；两个 UI 的 partial/unknown 状态有实际浏览器证据。真实模型调用为零。
